## Submission checklist

Everything is submitted from the [Team Dashboard](https://www.ohack.dev/hack/fall-2026/manageteam); judges read the dashboard, the README and the demo video.

- [ ] **Code pushed** to this repo, in small PRs (see `AGENTS.md`); judges and future recruiters read the history
- [ ] **Project story** written on the dashboard (`#project`): the problem, who it helps, what we built, what's next
- [ ] **Demo video** (4 minutes or less) on YouTube, Vimeo, Loom or Google Drive, linked on the dashboard (`#demo`); show it working, not slides
- [ ] **Submit** on the dashboard (editing is possible until the close)
- [ ] README current: what it does, how to run it, live link, demo link, team
- Optional: a [DevPost entry](https://opportunity-hack-2026-arizona.devpost.com/); the dashboard is the submission of record.

Judges score **Scope, Documentation, Polish and Security**, plus a separate **Accessibility** prize. The rubric is at [ohack.dev/hackathon-judging-criteria](https://www.ohack.dev/hackathon-judging-criteria). Work is documented as GitHub Issues: one per task or decision, closed by the PR that lands it.

## After the hackathon

Winning teams finish the project with the nonprofit. The [Definition of Done](https://www.ohack.dev/about/completion) (deployed, nonprofit sign-off, docs, open source) is tracked on the team page. Keep the repo public and the README honest.
